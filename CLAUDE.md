# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A real-time meeting copilot in Python (`copilot/`) for Windows, Linux and macOS. It captures the mic and the system audio, does VAD chunking, transcribes with faster-whisper (CUDA, or CPU when no NVIDIA GPU is usable), and calls a cloud AI with an Ollama fallback. The UI is a local web page. See README.md for setup, hotkeys and the pipeline overview, and `tickets/` for the roadmap (Echo ticket format, `tickets/backlog/NNN_*.md`; commits reference `(#NNN)`).

The project is open source (MIT) at `github.com/masrisystems/meeting-copilot` (remote `public`). The private repo `masrisystems/meetings` (remote `origin`) has the same `main` plus the `legacy` branch, which holds the old Meetily-based Node scripts and private knowledge files. Never commit `knowledge_base/`, `knowledge_base.json`, `facts.json`, `.env` or `sessions/`: they are the user's private data and are git-ignored. Public samples live in `examples/`.

## Commands

```sh
uv sync                                        # Python 3.12 env (pinned; 3.13+ lacks reliable wheels)
uv run python -m copilot [--no-browser --no-hotkeys --fresh-facts]
uv run pytest                                  # all unit tests (no audio/GPU), CI: .github/workflows/ci.yml
uv run pytest tests/test_core.py::test_echo_mic_before_loopback_is_retracted   # single test
uv run python -m copilot.stt_bench file.wav    # real VAD + Whisper latency on a WAV
uv run python -m copilot.llm_bench [model ...] # local LLM: p50/p95, JSON validity, samples per Ollama model
uv run python -m copilot.devices               # device list + live levels
uv run python -m copilot.rag index | search "<query>"
```

## Architecture notes (non-obvious parts)

Terms (STT engine, STT model, Whisper) follow `GLOSSARY.md`.

- **Threads vs loop:** each audio source has a `VadWorker` thread, and one `SttWorker` thread owns the STT engine. Everything else (assistant, memory loop, LLM, FastAPI/uvicorn, WebSocket) runs on one asyncio loop. Segments cross over via `loop.call_soon_threadsafe(assistant.on_segment, seg)`. `Hub.publish` must only be called on the loop.
- **Platforms** (`audio.py`): one `_Source` interface (`device["name"]`, `queue`, `level`, `start/stop`) with three backends. Windows: `pyaudiowpatch` WASAPI mic + loopback. Linux: one `parec` subprocess per source, `@DEFAULT_SOURCE@` / `@DEFAULT_MONITOR@`, PulseAudio resamples to 16 kHz mono float32. macOS: `sounddevice`; the loopback is a virtual device (BlackHole), since CoreAudio has none. Platform packages are gated with `sys_platform` markers in `pyproject.toml`; import them only inside the matching branch. Hotkeys: `RegisterHotKey` on its own message-loop thread on Windows (a low-level hook gets dropped by Windows under load), `pynput` elsewhere (X11 only on Linux); failures only print a hint. CI runs tests and import smoke checks on all three OSes.
- **STT engine** (`stt.py`): `stt_engine(setting, system, machine, binary)` is the pure choice, returning `(engine, reason)`: `auto` is WhisperKit only on macOS arm64 (`platform.machine()`; Intel Macs, Windows and Linux stay on faster-whisper), and a missing `whisperkit-cli` gives faster-whisper plus a reason ("requested but unavailable" when `STT_ENGINE=whisperkit`). `chosen_stt_engine()` feeds it the real machine. `build_stt_engine()` is the only place an engine is constructed (`SttWorker`, `stt_bench`); it also runs `warm_up()`, and a WhisperKit that fails to get its model, start, become healthy or warm up is closed and replaced by faster-whisper, with the reason printed. The app never installs anything. An engine then serves `transcribe(chunk) -> Segment | None` and `close()`. `segment.py` holds what every engine shares (`Segment`, `is_hallucination`, `StickyLanguage` for the per-source language and its re-detection schedule), so `whisperkit.py` does not import `stt.py`.
- **WhisperKit** (`whisperkit.py`, `STT_ENGINE=whisperkit`): runs Homebrew's `whisperkit-cli serve` as a child on a free localhost port with `--model-path` from `whisperkit.model_path()`: `WHISPERKIT_MODEL_PATH`, then MacWhisper's models folder (read-only, the configured `WHISPERKIT_MODEL`, never MacWhisper's selection), then the Hugging Face cache (`snapshot_download(local_files_only=True)`, which also rejects an interrupted download), else only that model's subfolder of `argmaxinc/whisperkit-coreml` is downloaded into the cache in the STT thread (the tokenizer, a few MB and not in that subfolder, is still fetched by `whisperkit-cli` into `~/Documents/huggingface`). Other flags: `--temperature-fallback-count 0` and `WHISPERKIT_COMPUTE_UNITS` (default `cpuAndGPU`: ~0.3 s/chunk on an M4 Max vs ~0.7 s on the Neural Engine at the same accuracy; step 0 table in ticket 013) for encoder and decoder; output goes to `sessions/whisperkit.log`. The server requires a `model` form field. No prompt is ever sent: WhisperKit pre-fills it through the decoder (2x latency) and it caused repetition loops; segments above `WHISPERKIT_MAX_COMPRESSION` are dropped instead. The server has no language probabilities, so a detected language outside `LANGUAGES` is discarded and the chunk is re-sent in the sticky language (`LANGUAGES[0]` on a source's first chunk). The child is stopped by `close()` (`__main__` joins the STT worker on shutdown) with `atexit` as the backstop; `cli()` maps SIGTERM to `KeyboardInterrupt` because uvicorn re-raises the signal after shutdown, which would otherwise skip all cleanup. **Crash recovery:** a connection-level request failure (`httpx.TransportError`, including the 30 s timeout) or a 5xx reply restarts the server once per run (new port) and re-sends the chunk in flight (reported as `stt` events through the `on_status` that `SttWorker` passes via `build_stt_engine(on_status=...)`: not ready with the restart `note`, then ready); the next failure, or a failed restart, raises `segment.EngineFailed`. `SttWorker` then closes the engine, builds faster-whisper (`build_stt_engine("faster-whisper")`) for the rest of the run, transcribes the same chunk on it, and reports through `on_status` (`stt` events with `ready`, `engine` and the `note` saying why). `WhisperKitEngine(launch=...)` takes the server factory, which is the test seam (fake HTTP servers that can be killed).
- **faster-whisper settings** (`stt.whisper_settings`; `WHISPER_LANGUAGE` applies to both engines): `WHISPER_DEVICE/MODEL/COMPUTE=auto` resolve via `ctranslate2.get_cuda_device_count()` to `large-v3-turbo`/`float16` on CUDA or `small`/`int8` on CPU.
- **CUDA DLLs:** `copilot/cuda.py` must be imported before faster_whisper/ctranslate2. On Windows it registers the pip-installed `nvidia/*/bin` dirs (no-op elsewhere; Linux uses system CUDA libraries). `stt.py` does this.
- **Silero VAD** uses the ONNX file bundled with faster-whisper (`faster_whisper/assets/silero_vad_v6.onnx`), run frame by frame. The v6 model needs the previous frame's last 64 samples prepended (input `(1, 576)`). `Chunker` is pure logic and unit-tested; `SileroStream` is stateful.
- **WASAPI loopback sends no data while output is silent.** `VadWorker` feeds synthetic silence on queue timeouts so open utterances still end.
- **Whisper latency:** auto language detection costs a full extra encoder pass (~240 ms), so the language is sticky per source and re-detected every `LANG_DETECT_EVERY` chunks. `temperature=0.0` disables the fallback re-decodes. Models load with `local_files_only=True` first, because the HF freshness check can take minutes.
- **Echo handling** (`transcript.py`): a mic segment that fuzzy-matches a recent loopback segment is dropped. If the mic copy arrived first, it is retracted (removed from `turns` and `segments`), and the UI receives a `retract` event.
- **Context sent to the LLM** (`Assistant._context`): `[FACTS]` + `[MEMORY]` + `[KNOWLEDGE]` + `[TRANSCRIPT]` (last `MAX_TURNS` turns). `Transcript.turns` is a short deque; `Transcript.segments` keeps the whole meeting for `memory.py`, which folds segments newer than its id cursor into a rolling summary every `MEMORY_INTERVAL_S`.
- **Prompts:** `PROMPT` in `.env` selects `copilot/prompts/<name>.md` (`system` for sales calls, `interview`). Every prompt must keep the same JSON output format as `SUGGESTION_SCHEMA` in `llm.py`.
- **Providers** (`providers.py`): one interface, `complete(system, prompt, schema) -> str`, implemented by `GeminiProvider`, `ClaudeProvider` (anthropic SDK, `output_config` json_schema + effort, server-side refusal `fallbacks: "default"` on Opus/Sonnet 5.x, never send `temperature`), `OpenAICompatProvider` (openai SDK with `base_url`; used for `openai`, `grok`, `custom`/OmniRoute; JSON mode downgrades schema -> object -> prompt when an endpoint rejects `response_format`), and `OllamaProvider` (thinking is always off: every chat request and the warm-up send `think: false`, with no setting, because the fallback exists to be fast; models without a thinking mode ignore it). All SDKs run with `max_retries=0`, because `llm.py` owns failover. `retry_after()` maps 429s (header or Gemini `retryDelay`) to a pause.
- **LLM** (`llm.py`): the primary is selected by `LLM_PROVIDER` and switched live from the UI (`set_primary`, a `providers` event). The call is hedged: after `CLOUD_TIMEOUT_S` Ollama starts in parallel and the first success wins. Only errors trip the breaker, not slowness. `llm.note` explains to the UI why the cloud is off. `SUGGESTION_SCHEMA` is closed (`additionalProperties: false`) for Claude and OpenAI strict mode. Gemini's free tier is about 20 requests/day/model, which is unusable for meetings.
- **Proactive scheduling** (`assistant.py`): fires at the end of a participant turn (debounce `PROACTIVE_DEBOUNCE_S`), capped at `PROACTIVE_MAX_PENDING_S` for monologues. It is single-flight with one trailing re-run, so at most one proactive LLM call is in flight. A trigger equal to the last one within `PROACTIVE_REPEAT_S` is dropped. The UI (`index.html`) holds the top card for `read_s` (sent in the `ui` event), while `user_speaking` (mic VAD state in `levels`) and while a card is pinned; newer cards wait in a one-slot queue. History replays carry `replay: true` and bypass the queue.
- **Knowledge paths** (`config.py`): `knowledge_base/` and `knowledge_base.json` start empty (no fallback to `examples/`, which only holds samples). `KB_EXTRA_PATHS` adds files or folders. The index lives in `db_py/`; `rag.sync()` re-indexes only when the file signature in `db_py/sources.json` changed, and `rag.watch()` runs it at startup and on every change. An empty source set drops the table.
- **Meetings** (`assistant.py`): the app starts idle. `start_meeting()` creates a new session (transcript, memory) and opens the devices through `open_capture` (the `Capture` is built lazily on the first start, so device errors become a `meeting` event with `error` instead of a crash). Sources are opened and closed on start/stop/mute, so `_Source.start()/stop()` must be idempotent and restartable on every backend.
- **Ollama models** (`llm.py`): `check_ollama()` polls `/api/tags` every 30 s; `describe()` carries `ollama_models` and `ollama_note`. The UI lists each model as `ollama:<model>`, and `set_primary("ollama:<model>")` switches the model of the one Ollama provider (primary and fallback).
- **Local LLM benchmark** (`llm_bench.py`, data in `llm_bench.json`, synthetic only): builds the real `OllamaProvider` and imports the prompt pieces from `assistant.py` (`suggestion_system`, `meeting_context`, `PROACTIVE_INSTRUCTION`, `TRANSLATE_SYSTEM`, `translation_target`, `TRANSLITERATE_SYSTEM`), so a change to the meeting prompts is measured as is. It needs a running Ollama, so CI only import-checks it.
- **State files:** running the app writes to the real `facts.json` and `sessions/`, so tests use `tmp_path`.
- **Install / launchers:** `install.sh` (Linux .desktop, macOS .app bundle) and `install.ps1` (Windows .lnk via pythonw) start `.venv` python with `--exit-on-close --log sessions/copilot.log`. Both prepare the STT model with `python -m copilot.stt` (builds, warms and closes the chosen engine; a named entry point, because their `||` fallback hides any failure). On macOS arm64 `install.sh` runs `brew install whisperkit-cli` (hint without Homebrew). `whisperkit.binary()` also looks in `/opt/homebrew/bin` and `/usr/local/bin`, because apps started from Finder or the Dock get no Homebrew `PATH`. The icon master is `copilot/web/icon.svg` (also the favicon); `packaging/icon.png` (1024) and `icon.ico` are rendered from it.
- **Meeting records** (`export.py`): `stop_meeting()` returns a task that summarizes the last minutes, waits for the meeting's running transliterations (both within 30 s) and writes `MEETINGS_DIR/Meeting <date> <time>.md`; it works on the old meeting's objects because a new meeting may already run. `__main__` awaits it on shutdown during a meeting. Suggestions and answers go through `Assistant._card` so they are recorded.
- **Window** (`window.py`): always-on-top and opacity for the Chrome `--app` window, found by its exact title "Meeting Copilot" (Win32 API on Windows, EWMH client messages/properties via python-xlib on X11; unsupported on Wayland/macOS). Applied whenever a page connects (with retries) and persisted in `settings.json`.
- **Languages:** `LANGUAGES` (first = the user's) restricts Whisper's detection and sets the translation target; `REPLY_LANGUAGE` appends a language rule to the system prompt and sets the language of the meeting memory, body and headings (`memory.system_prompt`; empty = German with the German headings), which the panel and the meeting record show as written; `TRANSLITERATE` lists languages whose segments (either source) get a plain-text LLM call for a Latin-script rewrite (`transliteration` event, replaced in place in the UI, replayed with the history). It shares translation's one-at-a-time queue and `PLAIN_MAX_WAIT_S` (`Assistant._plain`, which skips lines with `Segment.retracted`, set by `Transcript.add` on an echo, or from an ended meeting) and never changes the text in `Transcript`, so the LLM context, facts and memory keep the original script; the result is kept as `Segment.transliteration` (`Transcript.transliterate`, which rewrites that segment's session log entry in place), and the meeting record shows it, falling back to the original; `EMBEDDING_MODEL` is part of the index signature, so changing it re-indexes. `UI_LANGUAGE` (`strings.py`, `en`/`de`, unknown = `en` with a console hint) sets the text the copilot writes for the window and the headings and labels of the meeting record (`export.render`; the LLM-written memory stays as written): server notes go through `strings.t(key, **params)`, and an error shown in the window is raised as `strings.UiError(key, ...)`, whose `str()` stays English for the console while `ui_text(e)` follows `UI_LANGUAGE`. Console log lines stay English.
- UI rule from the user's global instructions: no emojis; use inline SVG icons.
